# Дитячий розклад · Family School Web

[![License: MIT](https://img.shields.io/badge/License-MIT-blue.svg)](LICENSE)

Статичний вебзастосунок для ведення шкільного розкладу, домашніх завдань і контрольних для кількох дітей. Не потребує бекенда, бази даних чи збірки: усі дані читаються з файлу `schedule.json` поруч із застосунком, а редагування зберігається локально в браузері.

Публікація оновлень — простим пушем файлу `schedule.json` у репозиторій GitHub Pages. Усі, у кого є посилання, бачать актуальний розклад — Service Worker підхоплює нову версію автоматично.

Інтерфейс — українською мовою, тема — темна, макет адаптований під телефон і планшет.

## Можливості

**Розклад**
- Тижнева таблиця 7 × 10: 8 уроків + 2 додаткові заняття (гуртки, тренування).
- Редактор «Розклад дзвінків»: час початку й кінця кожного уроку, назва та час для додаткових занять.
- Картки уроків із назвою предмета та вчителем/кабінетом.
- Переміщення карток drag & drop між будь-якими днями та рядками (обмін місцями, якщо ціль зайнята).

**Кольори предметів**
- Палітра з 12 кольорів + довільний колір через `<input type="color">`.
- Колір прив'язаний до **предмета**, а не до окремої клітинки: змінили колір «Математика» — оновилися всі картки математики за тиждень.
- Автодоповнення з уже використаних предметів (`<datalist>`).

**Діти**
- Кілька дітей, вкладки з кольоровим маркером, швидке перемикання.
- Для кожної дитини окремо: ім'я, клас, колір вкладки, власний розклад дзвінків, розклад, домашка й контрольні.

**Завдання й контрольні**
- Домашні завдання: предмет, опис, дата, клас/нотатка, чекбокс виконаного.
- Контрольні та іспити: предмет, опис, дата, кабінет.
- Кнопка **«Видалити»** у редакторі — видалення записів безповоротно.

**Дані**
- Читання розкладу з `schedule.json` поруч із `index.html` (публічно, без токенів).
- Локальне збереження змін у `localStorage`.
- Експорт JSON у форматі, готовому до пушу в репозиторій.
- Імпорт JSON з файлу.
- Індикатор стану у верхній панелі:
  - 🟢 зелений — дані завантажено з сервера;
  - 🔵 синій — є локальні зміни, які ще не опубліковано;
  - 🟡 жовтий — триває завантаження;
  - 🔴 червоний — помилка завантаження.
- Service Worker для офлайн-режиму та повідомлення про нову версію.

## Швидкий старт

Проєкт не потребує встановлення залежностей чи збірки — це чотири статичні файли + `schedule.json`.

**Варіант 1 — локальний вебсервер (рекомендовано)**

```bash
# Python 3
python -m http.server 8000

# або Node.js
npx serve .
```

Далі відкрийте <http://localhost:8000>.

> Service Worker працює лише за HTTP(S), не з `file://`. Для локальної розробки завжди використовуйте локальний сервер.

**Варіант 2 — GitHub Pages**

1. Покладіть у корінь репозиторію: `index.html`, `style.css`, `app.js`, `sw.js`, `schedule.json`.
2. Repo → **Settings → Pages → Deploy from a branch** → `main` / `root` → **Save**.
3. Через хвилину застосунок доступний за адресою `https://<user>.github.io/<repo>/`.

## Як користуватися

1. Відкрийте застосунок за посиланням.
2. Натисніть **＋** у верхній панелі (або «Додати дитину» у бічному меню ☰) —
   вкажіть ім'я, клас і колір вкладки.
3. Натисніть **«Розклад дзвінків»** — задайте час початку/кінця для 8 уроків і
   назви та час для 2 додаткових занять.
4. Натискайте на порожні комірки («+ Додати урок») і заповнюйте предмет,
   вчителя/кабінет та колір.
5. Додавайте домашні завдання (**+ Домашка**) і контрольні (**+ Контрольна**).
6. Коли готові — натисніть **«Експорт JSON»** і опублікуйте файл (див. нижче).

> **Порада.** Якщо назва предмета вже існувала, редактор автоматично підставить
> її колір. Щоб задати колір усьому предмету — виберіть його на будь-якій картці
> й збережіть: усі картки з цією назвою стануть того самого кольору.

## Публікація змін

Розклад зберігається в одному JSON-файлі, який лежить прямо в репозиторії поруч із застосунком.

### Робочий цикл

1. Відкриваєте застосунок → редагуєте розклад.
2. Дані одразу зберігаються в `localStorage` вашого браузера.
3. Індикатор стає **🔵 синім** — «є локальні зміни».
4. Тиснете **«Експорт JSON»** — з'явиться інструкція та завантажиться файл `schedule.json`.
5. Замінюєте цим файлом старий `schedule.json` у репозиторії (commit + push).
6. Через 1–2 хвилини GitHub Pages роздає нову версію.
7. У всіх, хто відкрив застосунок, з'являється тост **«Доступна нова версія розкладу»** з кнопкою «Оновити».

### Кнопка «Оновити з сервера»

Якщо ви редагували локально, але хочете відкинути зміни і повернутися до опублікованої версії:

- Меню ☰ → **«Оновити з сервера»** або кнопка у футері.
- Підтвердьте — локальні дані буде перезаписано серверними.

### Локальні зміни vs серверна версія

- Якщо в `localStorage` є **позначка про локальні зміни**, при завантаженні застосунок **не перетирає** їх серверною версією.
- Позначка знімається лише після **«Оновити з сервера»** або **«Імпорт JSON»**.
- Це не система реального часу — якщо редагуєте на кількох пристроях, «переможе» той, хто останнім експортує та пушить.

## Синхронізація між пристроями

Централізованої синхронізації немає. Спільним джерелом істини є файл `schedule.json` у репозиторії. Усі пристрої читають один і той самий файл — тому змін достатньо опублікувати один раз.

Якщо потрібно перенести локальні зміни з одного пристрою на інший без пушу — скористайтеся **«Експорт JSON»** на першому пристрої й **«Імпорт JSON»** на другому.

## Структура проєкту

```
.

├── sw.js                   # Service Worker: офлайн + нотифікація про оновлення
├── schedule.json           # публічний файл з даними (пушите оновлення сюди)
├── .gitignore
├── CHANGELOG.md
├── LICENSE                 # MIT
└── README.md
```

## Модель даних

Дані зберігаються одним ключем у `localStorage`:

| Ключ | Вміст |
|------|-------|
| `fsc.data.v1` | увесь розклад (`{ version, children }`) |
| `fsc.dirty.v1` | `"1"`, якщо є локальні незбережені зміни |

Формат `schedule.json` ідентичний формату локальних даних:

```jsonc
{
  "version": 1,
  "children": [
    {
      "id": "m0abc123x4",              // uid: час у base36 + випадковий суфікс
      "name": "Софія",
      "class": "5-А",
      "color": "#4c8df6",              // колір вкладки
      "slots": [                       // рівно 10 записів: 8 уроків + 2 додаткові
        { "num": "1",  "label": "",          "start": "08:00", "end": "08:45" },
        // ...
        { "num": "8",  "label": "",          "start": "14:30", "end": "15:15" },
        { "num": "★1", "label": "Гурток 1", "start": "16:00", "end": "17:00" },
        { "num": "★2", "label": "Гурток 2", "start": "17:15", "end": "18:15" }
      ],
      "days": {                        // 7 днів, у кожному масив із 10 комірок
        "mon": [ { "subject": "Математика", "room": "к. 203", "color": "#ffcf44" }, null, ... ],
        "tue": [ ... ], "wed": [ ... ], "thu": [ ... ],
        "fri": [ ... ], "sat": [ ... ], "sun": [ ... ]
      },
      "subjectColors": {               // колір прив'язаний до предмета (ключ — lowercase)
        "математика": { "name": "Математика", "color": "#ffcf44" }
      },
      "homework": [
        { "id": "…", "subject": "Математика", "text": "№ 1–24",
          "date": "2026-09-25", "done": false, "class": "5-А" }
      ],
      "exams": [
        { "id": "…", "subject": "Українська мова", "text": "Диктант",
          "date": "2026-10-02", "room": "к. 112" }
      ]
    }
  ]
}
```

**Дні тижня** зберігаються короткими ключами: `mon`, `tue`, `wed`, `thu`, `fri`, `sat`, `sun`.

**Мінімальний валідний файл** (для першого запуску):

```json
{ "version": 1, "children": [] }
```

**Стійкість до старих даних.** Під час завантаження виконуються `normalizeSlots()`, `normalizeDay()` і `normalizeData()`: вони доповнюють короткі масиви до 10 комірок і переносять колір, який раніше зберігався просто в картці уроку, у `subjectColors`. Старі дані відкриваються без ручного втручання.

### Експорт та імпорт

- **Експорт** — кнопка у футері або меню ☰ → «Експорт JSON». Файл
  `schedule.json` містить увесь об'єкт `data` у форматі, готовому до заміни в репозиторії. Після експорту з'являється модальне вікно з покроковою інструкцією.
- **Імпорт** — «Імпорт JSON» → вибір файлу. Перевіряється наявність поля
  `children`; помилка формату показується alert-повідомленням. **Імпорт замінює**
  поточні дані повністю та знімає позначку про локальні зміни.

## Service Worker

Файл `sw.js` реєструється при першому відкритті застосунку і забезпечує:

- **Офлайн-режим** — оболонка (`index.html`, `style.css`, `app.js`) кешується і працює без інтернету.
- **Свіжий `schedule.json`** — файл завжди тягнеться з мережі (`no-store`), кеш не використовується.
- **Нотифікацію про оновлення** — коли оболонка змінилася й нова версія SW встановлена, у нижній частині екрана з'являється тост «Доступна нова версія розкладу» з кнопкою «Оновити».

### Стратегії кешування

| Ресурс | Стратегія |
|--------|-----------|
| `schedule.json` | network-only, `cache: "no-store"` |
| `index.html`, `style.css`, `app.js` | network-first → fallback у кеш |
| Google Fonts | network → fallback у кеш |

### Форсоване оновлення застосунку

Щоб SW примусово оновив оболонку у всіх користувачів (наприклад, після зміни коду):

1. Відкрийте `sw.js`.
2. Змініть константу `CACHE_VERSION` (наприклад, `"fsc-v1"` → `"fsc-v2"`).
3. Пушніть зміни.
4. Наступного разу, коли користувач відкриє сайт, SW побачить нову версію, встановиться у фоні й покаже тост «Доступна нова версія розкладу».

## Вимоги до браузерів

Сучасний браузер із підтримкою ES2020: **Chrome / Edge 88+**, **Firefox 90+**, **Safari 15+**. Застосунок використовує `async/await`, `Map`/`Set`, `<datalist>`, нативні поля `date` / `time` / `color`, `fetch`, HTML5 Drag & Drop, Service Workers.

Зовнішніх залежностей немає; єдиний зовнішній ресурс — шрифт Inter із Google Fonts (застосунок працює й без нього — є `system-ui` у fallback).

| Можливість | Потрібне | Без цього |
|------------|----------|-----------|
| Розклад, домашка, контрольні | сучасний браузер | — |
| Читання опублікованого розкладу | HTTP(S) доступ до `schedule.json` | старт з порожніми даними |
| Збереження локальних змін | `localStorage` | дані зникають після закриття вкладки |
| Офлайн-режим і сповіщення про оновлення | Service Worker (HTTP(S), не `file://`) | працює лише онлайн, без нотифікацій |
| Переміщення карток | миша (HTML5 DnD) | на touch-екранах недоступне |

## Розробка

Збірка, лінтери й пакетний менеджер **не потрібні** — це навмисна перевага проєкту.

```bash
# запуск локально
python -m http.server 8000     # або: npx serve .

# швидка перевірка синтаксису
node --check app.js
node --check sw.js
```

**Точки розширення в `app.js`:**

| Ділянка | Призначення |
|---------|-------------|
| `DAYS`, `DAY_FULL` | дні тижня та їхні підписи |
| `LESSON_COUNT`, `EXTRA_COUNT`, `TOTAL_ROWS` | кількість рядків розкладу |
| `SUBJECT_PALETTE`, `DEFAULT_SUBJECT_COLOR` | палітра кольорів предметів |
| `LS_DATA`, `LS_DIRTY`, `REMOTE_FILE` | ключі сховища та ім'я публічного файлу |
| `defaultLessonSlots()`, `defaultExtraSlots()` | часи дзвінків за замовчуванням |
| `normalizeSlots()`, `normalizeDay()`, `normalizeData()` | сумісність зі старими даними |
| `loadAll()` / `saveLocal()` / `fetchRemote()` | читання та запис |
| `renderSchedule()` | побудова таблиці 7 × 10 і drag & drop |

Стилізація йде через CSS-змінні в `:root` (`--bg`, `--accent`, `--err` тощо), тому тему можна перефарбувати в одному місці.

## Розгортання на GitHub Pages

1. Покладіть у корінь репозиторію: `index.html`, `style.css`, `app.js`, `sw.js`, `schedule.json` (з мінімальним валідним вмістом).
2. **Settings → Pages → Deploy from a branch** → `main` / `root` → **Save**.
3. Через хвилину застосунок доступний за адресою `https://<user>.github.io/<repo>/`.

> Сайт працює по HTTPS — Service Worker реєструється без проблем, а `fetch` до
> `schedule.json` не має mixed-content обмежень.

## Відомі обмеження

| Проблема | Статус |
|----------|--------|
| Drag & drop не працює на touch-екранах | HTML5 DnD не підтримується на сенсорних пристроях; користуйтеся редактором уроку |
| CDN GitHub Pages може кешувати `schedule.json` до ~10 хв | Service Worker робить `no-store`, але edge-кеш GitHub — ні. Для миттєвої перевірки — hard reload (Ctrl+Shift+R) |
| Немає merge конфліктів | якщо редагуєте на кількох пристроях, останній експорт → пуш перемагає попередні |
| Немає авторизації | публічний файл — усі, хто має посилання, бачать розклад; не зберігайте секретні дані |
| Немає автоматичного тесту | ручна перевірка через `node --check` та відкриття в браузері |

2. Зробіть зміни — дотримуйтесь наявного стилю: `const` замість `var`,

3. Перевірте `node --check app.js` і відкрийте застосунок локально.
4. Оновіть `CHANGELOG.md` у секції `[Unreleased]`.
5. Відкрийте Pull Request.
