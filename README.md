# Дитячий розклад · Family School Web

[![License: MIT](https://img.shields.io/badge/License-MIT-blue.svg)](LICENSE)
[![Powered by Cloudflare Pages](https://img.shields.io/badge/Powered_by-Cloudflare_Pages-F38020?logo=cloudflare&logoColor=white)](https://pages.cloudflare.com/)

Вебзастосунок для ведення шкільного розкладу, домашніх завдань і контрольних для кількох дітей.

**Архітектура:**
- 🌐 Статичний фронтенд — HTML/CSS/JS, без збірки.
- ⚡ Cloudflare Pages Functions — маленький API для читання/запису.
- 🗄 Cloudflare KV — сховище одного JSON-файлу з розкладом.
- 📱 PWA — `manifest.json` + Service Worker: офлайн-кеш, автооновлення, встановлення як застосунок.
- 🔓 Читання розкладу — публічне, за посиланням, без авторизації.
- 🔒 Редагування — тільки з паролем (зберігається як Secret на Cloudflare).

Інтерфейс — українською, тема — темна, макет адаптований під телефон і планшет.

## Як це працює

```
┌─────────────────┐         GET /api/schedule (public)
│                 │  ──────────────────────────────────►  ┌──────────────┐
│   Браузер       │                                       │  Cloudflare  │
│  (застосунок)   │  PUT /api/schedule (X-Edit-Password)  │  Pages + KV  │
│                 │  ◄──────────────────────────────────  │              │
└─────────────────┘                                       └──────────────┘
       │
       ▼ localStorage (кеш + незбережені зміни)
```

- Усі, хто відкрив посилання, **бачать актуальний розклад** — API читання публічне.
- Хто ввів пароль → отримує кнопку **«💾 Зберегти на сервер»**, редагує в браузері, зберігає одним кліком.
- Локальні незбережені зміни живуть у `localStorage` — можна редагувати офлайн і зберегти пізніше.

## Можливості

**Розклад**
- Дві таблиці: **Пн–Пт** (8 уроків + 2 додаткові заняття) та **окрема таблиця вихідних** (Субота й Неділя — лише гуртки, по 2 слоти).
- Редактор «Розклад дзвінків»: час початку/кінця кожного уроку, назва додаткових занять.
- Картки уроків із назвою предмета та вчителем/кабінетом.
- Drag & drop між будь-якими днями та рядками (обмін місцями, якщо ціль зайнята; Ctrl/Cmd — копіювання). Гурток можна перетягнути з Пн–Пт у Сб/Нд і навпаки.

**Кольори предметів**
- Палітра з 12 кольорів + довільний колір.
- Колір прив'язаний до **предмета**, а не до окремої клітинки — зміна кольору в будь-якій картці миттєво перефарбовує всі картки цього предмета (включно з гуртками у вихідних).
- `subjectColors` — єдине джерело правди; `normalizeData()` вирівнює збережений `color` у клітинках під нього.
- Автодоповнення предметів через `<datalist>`.

**Діти**
- Кілька дітей, вкладки з кольоровим маркером.
- Для кожної окремо: ім'я, клас, колір вкладки, розклад дзвінків, розклад, домашка, контрольні.

**Завдання й контрольні**
- Домашні завдання: предмет, опис, дата, клас/нотатка, чекбокс виконаного.
- Контрольні та іспити: предмет, опис, дата, кабінет.
- Кнопка «Видалити» в редакторі — видалення записів безповоротно.

**Режими роботи**
- 👁 **Перегляд** (за замовчуванням) — усе видно, редагування вимкнено, банер зверху з кнопкою «Увійти для редагування».
- ✏️ **Редагування** (після введення пароля) — усі дії доступні, кнопка «Зберегти на сервер» у футері.

**Індикатор стану** (крапка в топбарі):
- 🟢 зелений — синхронізовано з сервером;
- 🔵 синій (пульсує) — є локальні незбережені зміни;
- 🟡 жовтий — триває збереження;
- 🔴 червоний — помилка;
- ⚪ сірий — режим перегляду.

**UX-дрібниці**
- ⌨️ **Ctrl+S** (Cmd+S на Mac) — швидке збереження на сервер.
- ⚠️ Попередження при закритті вкладки з незбереженими змінами.
- 💬 Тости про успіх/помилку операцій.
- 📁 Експорт/імпорт JSON — як резервний механізм.
- 🖨 **Друк розкладу** — кнопка 🖨 у топбарі (або меню ☰ → «🖨 Друк розкладу»): друкується лише таблиця розкладу на білому фоні з кольорами предметів, без темної теми та решти інтерфейсу.

**PWA — як застосунок**
- 📲 **Встановлення**: меню ☰ → **«📱 Встановити застосунок»** (на iOS — «Поділитися» → «На екран Домівка»).
- 📴 **Офлайн-режим**: app shell кешується Service Worker'ом; без мережі показується остання збережена версія розкладу з тостом «Офлайн-режим…».
- 🔄 **Автооновлення**: при виході нової версії — тост «Оновлення готове» → «Перезавантажити» (перевірка раз на годину та при поверненні до вкладки).
- 🎨 Іконки генеруються скриптом `tools/make-icons.py` (без залежностей, тільки Python stdlib).

**Мобільна версія**
- 📱 Адаптив для екранів <860px: компактний топбар, великі тап-таргети (≥40px), модалки майже на весь екран.
- ➡️ Таблиця розкладу горизонтально скролиться свайпом (scroll-snap); таблиця вихідних завжди вміщається в екран.
- 🔲 Підтримка notch / home indicator через `env(safe-area-inset-*)`.
- ⌨️ Без авто-zoom при вводі тексту в iOS Safari (шрифт полів ≥16px).

## Швидкий старт для користувача

1. Відкрийте застосунок за посиланням від адміністратора.
2. Ви побачите поточний розклад у режимі перегляду.
3. Щоб редагувати — меню ☰ → **«Режим редагування»** → введіть пароль.
4. Редагуйте як завгодно: додавайте дітей, уроки, домашку.
5. Натисніть **«💾 Зберегти на сервер»** — усі зміни стануть публічними.

## Розгортання на Cloudflare Pages

### Крок 1. Підготуйте репозиторій

Структура має бути такою:

```
your-repo/
├── functions/
│   └── api/
│       └── schedule.js
├── index.html
├── style.css
├── app.js
├── manifest.json
├── sw.js
├── icons/
└── (опційно) wrangler.toml, package.json
```

Запуште це у GitHub / GitLab.

> ⚠️ Перед деплоєм згенеруйте іконки: `python tools/make-icons.py`
> (без них PWA встановиться, але іконку застосунку не знайдено).

### Крок 2. Створіть Cloudflare Pages проєкт

1. Зареєструйтесь на <https://dash.cloudflare.com/> (безкоштовно).
2. Ліве меню → **Workers & Pages** → **Create** → вкладка **Pages** → **Connect to Git**.
3. Виберіть репозиторій, гілку `main`.
4. **Build settings:**
   - Framework preset: **None**
   - Build command: *(порожньо)*
   - Build output directory: `/` (або `.`)
5. Натисніть **Save and Deploy**.

Через хвилину проєкт доступний за адресою `https://<project>.pages.dev`.

### Крок 3. Створіть KV Namespace

1. Ліве меню → **Workers & Pages** → **KV**.
2. **Create namespace** → назва: `SCHEDULE_KV` → **Add**.
3. Скопіюйте виданий **Namespace ID** (знадобиться, якщо будете локально тестувати).

### Крок 4. Прив'яжіть KV до Pages-проєкту

1. Ваш Pages-проєкт → **Settings** → **Bindings** → **Add** → **KV namespace**.
2. **Variable name:** `SCHEDULE_KV` (саме така — вона використовується в коді).
3. **KV namespace:** виберіть той, що створили.
4. **Save**.

### Крок 5. Додайте пароль редагування

1. Той самий екран **Settings** → **Environment variables** → **Add**.
2. **Variable name:** `EDIT_PASSWORD`.
3. **Value:** ваш пароль (напр. `secret-passphrase-2026`).
4. **Type:** ⚠️ обов'язково **Secret** (щоб не показувався в дашборді).
5. Додайте як для **Production**, так і для **Preview** оточень.
6. **Save**.

### Крок 6. Перевиконайте деплой

Після зміни bindings/env потрібен новий деплой:
- Або зробіть коміт у гілку `main` — Pages задеплоїть автоматично.
- Або в дашборді проєкту: **Deployments** → **Retry deployment**.

### Крок 7. Готово

- Відкрийте `https://<project>.pages.dev` — розклад порожній.
- Меню ☰ → «Режим редагування» → введіть пароль → додайте дітей → «💾 Зберегти на сервер».
- Скиньте посилання родині — вони бачитимуть розклад у режимі перегляду.

### Крок 8. (Опційно) Власний домен

**Settings → Custom domains → Set up a custom domain** → виберіть домен, який керується через Cloudflare.

## Локальна розробка

Потрібен Node.js 18+ і `wrangler`.

```bash
# 1. Встановити wrangler
npm install

# 2. Створити KV для локального preview
npx wrangler kv namespace create SCHEDULE_KV
npx wrangler kv namespace create SCHEDULE_KV --preview
# → вписати обидва id у wrangler.toml

# 3. Створити .dev.vars з локальним паролем
echo "EDIT_PASSWORD=test123" > .dev.vars

# 4. Запустити
npm run dev
```

Відкриється <http://localhost:8788> — там працюють і статика, і `/api/schedule` через Wrangler.

**Швидка перевірка синтаксису:**

```bash
node --check app.js
node --check sw.js
node --check functions/api/schedule.js
```

## API

Простий REST на двох ендпоінтах.

### `GET /api/schedule`

Публічне читання розкладу. Без авторизації.

**Відповідь `200`:**
```json
{
  "version": 1,
  "children": [ ... ],
  "updatedAt": "2026-01-15T09:32:11.482Z"
}
```

Якщо KV порожній — повертається `{ "version": 1, "children": [], "updatedAt": null }`.

### `PUT /api/schedule`

Запис розкладу. Потребує заголовок `X-Edit-Password`.

**Приклад:**
```bash
curl -X PUT https://<project>.pages.dev/api/schedule \
  -H "Content-Type: application/json" \
  -H "X-Edit-Password: secret-passphrase-2026" \
  -d @schedule.json
```

**Відповіді:**
- `200 { "ok": true, "updatedAt": "..." }` — збережено.
- `400 { "error": "..." }` — некоректний JSON або відсутнє поле `children`.
- `401 { "error": "Невірний пароль" }` — пароль неправильний.
- `500 { "error": "..." }` — не налаштовано KV або `EDIT_PASSWORD`.

## Модель даних

Дані в KV та в `localStorage` мають однаковий формат:

```jsonc
{
  "version": 1,
  "updatedAt": "2026-01-15T09:32:11.482Z",  // додається сервером при PUT
  "children": [
    {
      "id": "m0abc123x4",
      "name": "Софія",
      "class": "5-А",
      "color": "#4c8df6",
      "slots": [
        { "num": "1",  "label": "",         "start": "08:00", "end": "08:45" },
        // ... 8 уроків усього ...
        { "num": "★1", "label": "Гурток 1", "start": "16:00", "end": "17:00" },
        { "num": "★2", "label": "Гурток 2", "start": "17:15", "end": "18:15" }
      ],
      "days": {
        "mon": [ { "subject": "Математика", "room": "к. 203", "color": "#ffcf44" }, null, ... ],
        "tue": [ ... ], "wed": [ ... ], "thu": [ ... ],
        "fri": [ ... ], "sat": [ ... ], "sun": [ ... ]
      },
      "subjectColors": {
        "математика": { "name": "Математика", "color": "#ffcf44" }
      },
      "homework": [
        { "id": "…", "subject": "Математика", "text": "№ 1–24",
          "date": "2026-09-25", "done": false, "class": "5-А" }
      ],
      "exams": [
        { "id": "…", "subject": "Українська мова", "text": "Диктант",
          "date": "2026-10-02", "room": "к. 112" }
      ]
    }
  ]
}
```

**Ключі `localStorage`:**

| Ключ | Вміст |
|------|-------|
| `fsc.data.v1` | увесь розклад |
| `fsc.dirty.v1` | `"1"`, якщо є незбережені локальні зміни |
| `fsc.password.v1` | пароль редагування (лише локально) |
| `fsc.updatedAt.v1` | час останнього успішного оновлення |

## Безпека

**Що захищено:**
- ✅ Пароль зберігається на Cloudflare як **Secret** — не видно в дашборді після збереження, не потрапляє в код і git.
- ✅ Пароль передається лише в заголовку `X-Edit-Password` на API того ж походження — не витікає в логи URL.
- ✅ Локально пароль зберігається тільки в `localStorage` вашого браузера.

**Що не захищено (не забувайте):**
- ⚠️ Читання розкладу **публічне** — не додавайте туди приватну інформацію (паролі від Zoom, домашні адреси, номери телефонів).
- ⚠️ Пароль — це «спільний секрет». Хто знає — той може редагувати. Немає «різних користувачів» / ACL.
- ⚠️ Немає rate limiting — теоретично можна брутфорсити. Використовуйте достатньо довгий пароль (16+ символів).

## Вимоги до браузерів

Сучасний браузер із підтримкою ES2020: **Chrome/Edge 88+**, **Firefox 90+**, **Safari 15+**.

Використовується: `async/await`, `Map`/`Set`, `<datalist>`, `date`/`time`/`color`, `fetch`, HTML5 Drag & Drop.

Зовнішній ресурс — тільки шрифт Inter із Google Fonts (є `system-ui` fallback).

Service Worker і встановлення PWA підтримуються всіма переліченими браузерами; на iOS додавання на екран Домівка — через меню «Поділитися» Safari.

## Відомі обмеження

| Проблема | Статус |
|----------|--------|
| Drag & drop не працює на touch-екранах | Обмеження HTML5 DnD; на телефоні використовуйте редактор клітинки |
| Немає merge конфліктів | Хто останній зберіг — того версія залишиться. Використовуйте «Оновити з сервера» перед редагуванням |
| Немає rate limiting на API | Використовуйте довгий пароль; за потреби додайте Cloudflare Turnstile |
| Один спільний пароль | Немає ACL — усі редактори мають однакові права |
| Cloudflare KV має eventual consistency | Після PUT нове значення видно глобально протягом ~1 хв |
| Іконки PWA не згенеровані | Виконайте `python tools/make-icons.py` — до цього встановлення покаже «іконку не знайдено» |
| Service Worker реєструється за шляхом `/sw.js` | Працює, коли застосунок у корені домену; для хостингу в підкаталозі змініть шлях у `app.js` |

## Розробка

Збірка й пакетний менеджер потрібні лише для локального запуску Wrangler.
Сам код — просто HTML/CSS/JS, редагуйте безпосередньо.

**Точки розширення в `app.js`:**

| Ділянка | Призначення |
|---------|-------------|
| `DAYS`, `WORKDAYS`, `WEEKEND_LIST`, `DAY_FULL` | дні тижня (усі / Пн–Пт / Сб–Нд) |
| `LESSON_COUNT`, `EXTRA_COUNT`, `TOTAL_ROWS` | кількість рядків |
| `SUBJECT_PALETTE` | палітра кольорів |
| `LS_DATA`, `LS_DIRTY`, `LS_PASSWORD`, `LS_UPDATED_AT` | ключі localStorage |
| `API_URL` | шлях до API (за замовчуванням `/api/schedule`) |
| `defaultLessonSlots()`, `defaultExtraSlots()` | дефолтні дзвінки |
| `normalizeData()` | сумісність зі старими даними |
| `fetchRemote()`, `pushRemote()`, `verifyPassword()` | робота з API |
| `renderSchedule()` | секції розкладу: Пн–Пт + окрема таблиця вихідних |
| `buildScheduleTable()` | таблиця для довільного набору днів і рядків (drag & drop усередині) |

Стилізація — через CSS-змінні в `:root`.
